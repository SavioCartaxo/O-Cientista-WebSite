Modelo Relacional

Neste artigo, exploraremos o modelo relacional - a base matemática por trás dos bancos de dados relacionais modernos. Veremos como os dados são organizados em tabelas, quais regras garantem sua consistência e como as operações de atualização interagem com essas regras.

Conceitos Básicos

O modelo de dados relacional foi proposto por E. F. Codd em 1970 e revolucionou a área de bancos de dados. Ele é baseado no conceito de relação, derivado da teoria dos conjuntos, e possui uma forte fundamentação matemática que serviu de base para a criação da linguagem SQL.

Na prática, os dados são organizados em tabelas compostas por linhas e colunas - uma estrutura simples, intuitiva e poderosa que facilita tanto o armazenamento quanto a consulta de informações.

Definições Informais

Antes de entrarmos nas definições formais, é útil compreender os conceitos de forma intuitiva. Uma relação pode ser entendida como uma tabela de valores, onde cada linha representa um fato do mundo real - chamada formalmente de tupla - e cada coluna representa uma característica dos dados - chamada de atributo.

Uma chave é um atributo, ou conjunto de atributos, capaz de identificar unicamente cada linha da tabela - por exemplo, o número de CPF pode ser uma chave que identifica uma pessoa em um BD. Em alguns casos, quando nenhum atributo natural serve como identificador único, utiliza-se um identificador artificial como chave primária.

Definições Formais

Esquema de Relação

O esquema de uma relação representa sua estrutura e é definido no formato R(A1, A2, ..., An), onde R é o nome da relação e cada Ai representa um atributo - ou seja, uma coluna da tabela. Cada atributo pertence a um domínio, que define o conjunto de valores válidos para aquele atributo.

Tupla

Uma tupla é um conjunto ordenado de valores pertencentes aos domínios definidos no esquema da relação. Cada linha de uma tabela corresponde a uma tupla - ou seja, a um registro armazenado no banco.

Estado da Relação

O estado de uma relação corresponde ao conjunto atual de tuplas armazenadas na tabela em um determinado momento. Esse estado também pode ser chamado de povoamento da relação - e muda a cada operação de inserção, remoção ou atualização de dados.

Características das Relações

Ordenação

As tuplas de uma relação não possuem ordenação obrigatória - a ordem em que aparecem não carrega nenhum significado especial. Já os atributos normalmente são tratados de forma ordenada dentro do esquema da relação.

Atomicidade

Todos os valores de uma tupla devem ser atômicos - ou seja, indivisíveis. Isso significa que cada célula da tabela deve conter um único valor, sem listas ou estruturas aninhadas.

Domínio

Cada valor armazenado deve pertencer ao domínio definido para o atributo correspondente. Por exemplo, um atributo do tipo inteiro não pode receber um valor textual.

Notação

Os valores de uma tupla podem ser acessados utilizando a notação t[Ai] ou t.Ai, onde t é a tupla e Ai é o atributo desejado.

Constraints (Restrições)

As constraints definem quais valores são permitidos em um banco de dados, garantindo a integridade e a consistência das informações. Existem três tipos principais:

Restrições Inerentes

São restrições impostas pela própria natureza do modelo relacional, independentemente de qualquer definição explícita. Um exemplo clássico é a proibição de tuplas duplicadas - em uma relação, não podem existir duas linhas idênticas.

Restrições Baseadas no Esquema

São regras explicitamente definidas no banco de dados e normalmente implementadas por meio de SQL. Incluem restrições de domínio, chaves primárias, chaves estrangeiras e restrições de integridade.

Restrições Semânticas

São regras de negócio específicas da aplicação que não podem ser expressas diretamente no esquema do banco. Geralmente são implementadas no nível da aplicação, por meio de validações no código.

Restrições de Integridade

Restrição de Domínio

Todo valor armazenado deve pertencer ao domínio definido para o atributo - garantindo que os dados sejam sempre do tipo e formato esperados.

Restrição de Chave

As chaves garantem a unicidade das tuplas dentro de uma relação - nenhuma chave pode se repetir entre linhas diferentes da tabela.

Superchave

Uma superchave é um conjunto de atributos capaz de identificar unicamente uma tupla. Toda chave é uma superchave, mas nem toda superchave é uma chave.

Chave

Uma chave é uma superchave mínima - ou seja, nenhum de seus atributos pode ser removido sem perder a propriedade de unicidade.

Chave Primária

A chave primária é escolhida entre as chaves candidatas para identificar unicamente cada tupla da relação. Seus valores não podem ser nulos e não podem se repetir.

Integridade de Entidade

A integridade de entidade estabelece que os atributos que compõem a chave primária não podem possuir valores NULL. Essa restrição garante que cada tupla possa ser identificada de forma única e inequívoca dentro da relação.

Integridade Referencial

A integridade referencial estabelece relações entre tabelas por meio de chaves estrangeiras. Uma chave estrangeira referencia a chave primária de outra relação, garantindo que os dados relacionados entre tabelas sejam sempre consistentes. Em outras palavras, não é possível referenciar um registro que não existe.

Esquema de Banco Relacional

Um esquema de banco de dados relacional é formado por um conjunto de relações e suas restrições de integridade. Cada relação possui atributos, domínios, chaves e constraints associadas - formando uma estrutura completa e coesa que representa o mini-mundo modelado.

Estado do Banco de Dados

O estado de um banco de dados corresponde ao conjunto de estados de todas as relações presentes no sistema em um determinado momento. Um estado é considerado válido quando respeita todas as restrições de integridade definidas no esquema.

Operações de Atualização

As três principais operações de manipulação de dados em um banco relacional são INSERT, DELETE e UPDATE. Todas devem respeitar as restrições de integridade definidas - caso contrário, a operação é rejeitada ou tratada por uma ação corretiva.

Possíveis Violações

Cada operação de atualização pode violar diferentes tipos de restrições:

INSERT

Uma inserção pode violar restrições de domínio - valor fora do tipo esperado - restrições de chave - valor duplicado - integridade de entidade - chave primária nula - e integridade referencial - chave estrangeira referenciando registro inexistente.

DELETE

Uma remoção pode violar a integridade referencial quando o registro removido é referenciado como chave estrangeira em outra tabela.

UPDATE

Uma atualização pode violar restrições de domínio, chave primária e integridade referencial, dependendo dos atributos modificados.

Ações de Correção

Quando uma violação é detectada, o banco pode adotar diferentes estratégias de correção:

  • RESTRICT - rejeita a operação que causaria a violação.
  • CASCADE - propaga a operação automaticamente para os registros relacionados.
  • SET NULL - define como NULL os valores que referenciam o registro afetado.

Resumo

  • Modelo relacional: proposto por E. F. Codd em 1970, organiza dados em tabelas com fundamentação matemática.
  • Relação: tabela composta por tuplas (linhas) e atributos (colunas).
  • Esquema: estrutura da relação - R(A1, A2, ..., An).
  • Estado: conjunto atual de tuplas armazenadas em um determinado momento.
  • Domínio: conjunto de valores válidos para um atributo.
  • Chave primária: atributo ou conjunto de atributos que identifica unicamente cada tupla - não pode ser nulo.
  • Integridade referencial: chaves estrangeiras devem referenciar registros existentes.
  • Operações: INSERT, DELETE e UPDATE devem respeitar todas as restrições de integridade.
  • Ações de correção: RESTRICT, CASCADE e SET NULL.
